# Atomic multi-file invoice aggregation

Status: accepted

## Goal and public interface

Add `invoice_totals.batch.aggregate_csv_files(paths: Iterable[str | os.PathLike[str]]) -> dict[tuple[str, str], int]`. Exact original `(customer, currency)` strings map to integer cents, including negative and zero totals. This reusable library API reads UTF-8 CSV files in caller order and returns a fresh dictionary with sorted key insertion only after every file has validated and closed successfully. Empty iterables and valid header-only files return `{}`; an empty file fails.

Reject a bare string/path-like collection, bytes paths, noniterable collections, and non-string/non-path-like members with `TypeError`. Resolve each member with `os.fspath` before its file-error boundary; require a string result. Consume the iterable lazily without catching its own errors. The API prints nothing and creates no output files.

## Options and decision

1. **Selected: share the existing stream accumulator.** Minimally extract ingestion from `report.py` into a private helper accepting the stream, source, totals, and exact invoice-ID locations. `prepare_report` calls it with fresh local state and retains its current duplicate diagnostic and CSV serialization. `batch.py` supplies batch-local state and requests both source locations in duplicate diagnostics. This keeps header, amount, record-start and CSV rules identical without changing the CLI boundary.
2. Reimplement parsing in `batch.py`: simpler initial separation, but duplicates validation and risks divergence.
3. Parse the rendered single-file CSV and combine reports: loses invoice IDs and cannot enforce global uniqueness; reject.

The shared helper preserves current validation order, including duplicate detection before amount parsing. Convert accepted `Decimal` tuples to integer cents using the existing conversion; aggregate with Python integers, never context-sensitive decimal addition.

## Validation and failure boundaries

Open each file with `encoding="utf-8", newline=""` and close it before advancing to the next path. Reuse strict CSV parsing, exact named headers, allowed unique extra columns, exact record widths, required-value blankness checks, and unchanged `parse_amount` semantics. Preserve original strings; stripping is only for blankness checks. No normalization, conversion, dependencies, persistence, CLI flags or formats are added. Python 3.12+ and standard-library-only operation remain required.

Track each exact invoice ID as `(source, physical_record_start_line)` across the batch. Duplicates invalidate the entire call, including repeats across different groups or a repeated path. Diagnose current file/record-start line, `invoice_id`, value, and first file/record-start line; multiline values must not shift those positions. Retain zero groups and never combine currencies.

Use the existing `invoice_totals.report.InvoiceInputError` for invoice/CSV and expected file/encoding failures. Preserve exception causes when wrapping. Domain errors identify record starts; CSV errors use the available reader line; encoding errors identify the available decoder byte position without claiming a file-global offset; open/read/close failures identify the source and `file` reason. Embedded-NUL filenames are file-input errors; convert their known open-time `ValueError` narrowly. Avoid blanket catches, especially around iterable advancement or path conversion. State is private to each call, so failures cannot expose a partial mapping or affect later calls.
